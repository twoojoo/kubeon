# Contributing to Kubeon

Bug reports, ideas and pull requests are welcome. For larger changes (a new view, a new panel, a
change to the vendored k9s) open an issue first so we can agree on the approach.

## Setup

You need Go (version in `go.mod`), Docker (for the disposable kind cluster) and, on Linux, the Gio
development headers listed in `.github/workflows/ci.yml` (`GIO_LINUX_DEPS`).

```sh
make dev-up     # disposable kind cluster "kubeon-dev" → .dev/kubeconfig, with test fixtures
make run        # dev build against the kind cluster
make test       # unit tests
make test-int   # backend integration + headless UI tests (screenshots in .dev/shots)
make dev-down
```

Dev builds (`dev` tag) only accept a kubeconfig inside a `.dev/` directory and contexts named
`kind-kubeon*`, and keep client-go caches in `.dev/cache`: the clusters configured on your machine
are never touched. Run them with `env -u KUBECONFIG`.

## Guidelines

- Run `make test` before sending a pull request, and `make test-int` when you touch the backend or
  the UI (look at the screenshots in `.dev/shots/` after UI changes).
- UI mutations must go through the context policies (`allowMutation` / `guard` / `confirmMutation`
  in `internal/ui/policy.go`): protected and read-only contexts must keep working.
- Tests must not call paid LLM APIs: use the mock servers in `internal/ai/*_test.go` or a local
  Ollama model.
- `third_party/k9s` is generated by `scripts/vendor-k9s.sh` and `third_party/gio` by
  `scripts/vendor-gio.sh`: change them through `third_party/_k9s-overlay`, `third_party/_k9s-patches`
  or `third_party/_gio-patches`, not by editing the vendored files.
- Keep pull requests focused, with tests for the behaviour they change.

## Developer Certificate of Origin

Kubeon is licensed under the GPL-3.0-or-later and contributions are accepted under the same license.
Every commit must be signed off, certifying the [Developer Certificate of Origin](https://developercertificate.org/):

```sh
git commit -s -m "Fix log follow after container restart"
```

which adds a `Signed-off-by: Your Name <you@example.com>` line with your real name.
